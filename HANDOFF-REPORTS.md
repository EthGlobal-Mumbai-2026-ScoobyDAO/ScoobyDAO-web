# Reports integration handoff

Web app owns the Reports navigation, list/detail and asset adapter. The standalone reader is owned by the report-frontend workstream; backend owns the API, worker and immutable artifacts. A human teammate owns publication and authenticated sign-off. This change does not implement those functions.

By default the report list is empty. For local development only, set `NEXT_PUBLIC_REPORT_API_URL` to the origin of the explicitly configured loopback backend, for example `http://127.0.0.1:50653`, and use the web origin allowed by its CORS configuration. This unauthenticated operator API must not be exposed publicly. The adapter consumes GET /reports and GET /reports/{id}/{version}/artifacts, checks report/candidate/version/digest agreement, hashes exact report bytes and HTML before displaying, and verifies individual artifact bytes on download. It rejects non-loopback API origins, unsafe artifact paths and mismatched identities or hashes. Immutable backend delivery is still needed to avoid a change between HTML verification and iframe loading. The backend must continue to enforce version/digest binding and verified package assets. CORS is not authorization.

The iframe uses `allow-scripts` only, with no same-origin, forms, popups or top-navigation privileges. HTML is a coherent package with relative assets; downloading HTML alone does not package those assets. Serve untrusted HTML from an isolated artifact origin with a restrictive CSP and authenticated access before any production use. Never add `allow-same-origin` to the sandbox. The current local PDF is an unverified draft; full per-page QA is owned by backend. Review and operator strings are not authenticated approval. Selection and reference labels do not authorize publication.

The local reference RAY is source-curated, integration-only, not gate-qualified, and pending unauthenticated review. Its current sell simulation and gate calls succeeded; a live sell trap is not established. Do not substitute or publish that case as a default. Run `npm ci`, configure the API origin, then `npm run dev` and visit `/reports`. Run `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build`. The app retains its existing fixtures and other routes.

## Verification and remaining issues

The adapter was exercised against the local RAY API: list and artifact metadata agreed on report ID, candidate, version and report digest, and report and HTML byte hashes matched. Vitest passed 6 files / 30 tests and ESLint passed. Isolated Edge tests of the actual app at 1440px and 375px rendered all five pillars and one supplied chart, with CORS working; the reader has document-level horizontal overflow at 375px in its pillar cards and citation links. The reader owner needs to fix and regenerate that artifact. The outer app did not overflow at either width. Typecheck and production build passed (the first build hit transient Google font timeouts; the retry passed). List-to-detail navigation and Markdown download were verified against the expected digest. The worker can replace an existing job directory on retry, so current iframe loading has a verification-to-load race; immutable atomic artifact packages are a backend dependency.
