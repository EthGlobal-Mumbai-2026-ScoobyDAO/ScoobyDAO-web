Missing, mismatched or unsafe data fails closed. The legacy job-path fallback remains local development compatibility and does not provide immutable package guarantees.

## Separate legacy approval service

`NEXT_PUBLIC_API_URL` is a different legacy application API, with keccak manifest hashes, `POST /reports/:id/approve` and `GET /approvals/:id`; it is not the research API's report/version/SHA-256/package DTO. The current research backend does not implement those approval endpoints. The existing `/approve/[id]` screen displays returned approval state and a World App verification URI/QR; it does not verify World ID proofs itself. The user reports teammate work exists, but its repository, deployed endpoint, verifier, callback/domain and exact contract have not been located or tested in this checkout. Obtain those from the teammate before end-to-end smoke testing. Do not infer readiness from `/health` or point both base URLs at the research API.

Fixtures are enabled only by explicit `NEXT_PUBLIC_USE_FIXTURES=true` for demo/test; a network failure or incompatible approval response is an error, never an automatic simulated approval. The fixture path simulates sign-off and must be visibly treated as demo data. Once the teammate's service is available, configure its exact base URL, CORS and callback domain under that service's contract; keep credentials server-side. No secrets or callback URLs are specified here.
