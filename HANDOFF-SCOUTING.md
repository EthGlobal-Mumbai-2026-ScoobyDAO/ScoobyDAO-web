# Scouting Cases integration — active state

`/cases` separates a scouting board from the existing case/market demonstration. The scouting UI consumes only a versioned backend snapshot through `src/lib/scouting.ts`; it never falls back to sample candidates. With no configured service it explicitly says scouting is unavailable. The backend owns lane, human-action urgency and stable priority order; the web groups human attention first, then qualified/running research, and monitored leads. A separate historical-reference section explicitly says its distinct catalog is not connected. Source times and relative ages, verification status, evidence IDs and uncertainties remain visible. The snapshot TTL applies to the list snapshot only; it is not treated as a source-specific freshness rule. Older source context is not excluded solely because of age. The client displays no inferred scam probability or completed percentage. Unknown timestamps are not zero or proof of freshness.

The `scouting-case-list/1` adapter now matches the backend owner's in-progress GET `/scouting/cases` read shape; this is conditional local-prototype alignment, not an agreed frozen contract or a deployed API. It handles snapshot/policy digests, expiry, nullable references, reported access status, truncation, the backend's triggered/not-triggered/unknown/held evidence states, nullable symbols, backend-reported verified group counts and research pillar states. Set `NEXT_PUBLIC_SCOUTING_API_URL` to the explicitly trusted HTTPS origin, or loopback HTTP for local development. Paths, credentials, query strings and redirects are rejected; it is distinct from `NEXT_PUBLIC_API_URL` (legacy `/web/v1`) and `NEXT_PUBLIC_REPORT_API_URL` (report packages). Origin CORS/access policy belongs to backend. A real server must supply canonical candidate identities, evidence/uncertainty and backend-determined priority. The actual local read API has been browser-tested as recorded below; cross-workstream schema acceptance and authenticated verification remain separate.

The continuation button is disabled even if a response says it is available. Legacy backend fixture approvals now require explicit `NEXT_PUBLIC_USE_FIXTURES=true`; network failures never silently enable them. A separately authenticated, server-verified, revision-bound continuation endpoint is required before enabling it. Candidate selection, auto qualification and research do not establish authenticated report sign-off or publication. Existing case files, demo markets and the app's legacy fixture mode appear only behind a clearly labeled separate section; its historical fixture cards are marked as examples. The native Reports reader remains separate and unchanged. No new case, live scan, or fabricated result is created here.

To continue: record the shared local read-schema acceptance, merge the backend producer before deployment, implement any authenticated action only against an agreed verifier, and preserve reference/examples and snapshot/source-age distinctions. Owner is the web integration workstream; backend owns API and workflow; discovery owns evidence/verifiers; root coordinates. No schema change or automatic publication is authorized.

Verification at the WIP-alignment checkpoint: typecheck, lint and 17 Vitest files / 220 tests passed. Isolated 1440px/375px browser tests using a synthetic mocked WIP-shaped response covered priority order, lane/reference separation, stale states, disabled continuation even when a mock advertises availability, no writes, empty/error states, malicious-text escaping and no overflow. A separate browser check showed unconfigured scouting and an offline legacy approval error without simulated approval. These tests do not establish a live backend connection or validate an actual candidate.

The current runtime DTO accepts only live ETH/Base cases with `reference:null`; historical incidents and projects, including those without a verified token identity, belong to a separately versioned catalog interface. No historical reference identity is fabricated or copied into the live scouting schema.
