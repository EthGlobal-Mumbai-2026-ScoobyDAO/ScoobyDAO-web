# Scouting and Reports integration — 6 November 2026

The actionable Cases queue and Reports library share one app. The backend provides global actionability priority, evidence states and rationale. Cards use the existing cork/paper design and disclose full source details on demand. Provider claims are explicitly unverified; missing evidence is not a safety finding. Existing demo markets remain separate.

The v2 client supports `scouting-case-list/2`, including queued/running/partial/completed states and source-backed explanations. v1 remains read-compatible; its action semantics are not activated. In v2, an available human action sends a revision-bound challenge, launches a server-side World device attempt, displays the case and user code, and polls at the server-provided interval. It validates case, candidate, snapshot, policy, action, nonce and response states; it never submits a verified boolean. Cancellation, denied, expired, superseded, failed, unavailable and retry states are shown. The approved response triggers a case refresh, and backend-provided report identity links to the same Reports library. Existing failed/blocked runs can be retried only under the backend's authorization and expiry rules. World verification links are restricted to HTTPS world.org and subdomains, matching the checked-in World client target; this trust policy is not evidence of live authorization. Publication and report sign-off remain separate.

## Required admin boundaries — not implemented

The authoritative two-checkpoint charter and inventory are in backend PR #10 head `9423d15`. The current local action control and unprotected local draft readers are prototypes, not a consumer-safe or admin-authorized application. A World-verified identity alone does not establish administrator permission. Checkpoint 1 requires server-enforced admin session/reviewer access and a case-bound World confirmation before a human-exception investigation. Automatic admission bypasses that checkpoint only. Checkpoint 2 requires a separate admin/reviewer World decision bound to the generated immutable report and evidence; neither path currently implements that review queue or receipt. Consumers must not receive admin controls, device codes, private drafts or receipts. Sign-off and optional publication are distinct; approval does not publish automatically. Never expose the current unauthenticated local prototype as a production admin boundary. The synthetic journey above proves wiring, not these access controls, live World, reviewer enrollment, report sign-off or publication.
